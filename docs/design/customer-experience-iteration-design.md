## 3. 注册：方案 A（选型首屏）

```text
/sign-up
  └─ 首屏：仅两大选项（无账号表单）
        ├─ 个人账户 → 账号表单 → 个人钱包
        └─ 组织账户 → 账号表单 + 组织名称 → 新建组织（owner）
```

- 组织表单页突出组织名（分区标题 / 分隔 / 描边）。  
- OAuth 仅在进入表单页后、位于主按钮下方（§4）。  
- **已登录用户**可再次进入「创建组织」流程，新建另一个组织（§1.2 / 11.4），成为新组织 owner，不影响已加入的其它组织。

## 5. 额度：限额 + 可分配余额

```text
组织限额 customer.quota_limit     ← 超管设置
  └─ 已占用 = Σ 各工作区限额      ← 已确认口径
  └─ 可分配给工作区的余量 = 组织限额 − 已占用

工作区限额 workspace.quota_limit  ← 组织管理员设置
  └─ 已占用 ≥ 已分配给各成员组织钱包的额度（含未消耗余额）
  └─ 可分配给成员 = 工作区限额 − 已分配（±已用记账口径以实现为准）

成员组织钱包 balance              ← 仅「组织范围」密钥扣此账户
```

**文案：**「设置限额」「分配额度」；不用「充值」。

**入口（不再用独立「额度」页）：**

- 组织限额：超管在组织管理侧设置。  
- 工作区限额：组织管理员在「工作区」详情 / 编辑中设置。  
- 向成员分配：仅「成员与邀请」。  
- 成员看余额：组织「钱包」（§7）。  

现有组织侧栏 **「额度」菜单删除**（`/quota` 页随之下线，不必做成重定向入口）。组织「钱包」为**新增**菜单，承接「看自己的组织余额」，不承接旧划拨 UI。

**调低限额：** 新值不得低于已占用，否则拒绝并提示最低可设值。

## 6. 顶栏与组织页

### 6.1 顶栏

去掉：组织名、全局工作区下拉。  

**不做**：用户菜单内「加入的组织」列表（一人多组织仅靠组织页内筛选切换）。

### 6.1b 组织页「当前上下文」横幅（删除）

组织下各页（工作区、成员与邀请、额度/钱包、上游等）顶部的：

> 当前上下文: xxx（组织页按该工作区展示信息）

即 `WorkspaceContextBanner`——**整段删除**。

不再依赖顶栏/全局「当前工作区」决定整页数据范围；列表范围只由 **§6.2 页内筛选** 控制。

### 6.2 页内筛选

工作区、成员与邀请、钱包、上游/BYOK：

- 一人多组织时先筛 **组织**，再筛 **工作区**（`全部` | 具体工作区）；**默认均为「全部」**。  
- 「全部」下写操作须先选定具体组织 + 工作区。  

### 6.3 列表

成员 / 邀请列展示所属工作区；多工作区用 Tag 或「N 个」。组织「钱包」页按个人钱包同构展示当前用户自己的余额（可带工作区维度），不是成员列表。

## 7. 组织钱包

### 7.0 菜单与页面（对应需求：组织下新增「钱包」；下线「额度」）

**组织侧栏：去掉「额度」，新增「钱包」。** 超管、组织管理员、成员都能进入「钱包」；页面是「我的组织钱包」，不是全员钱包管理台。

```text
组织
  ├── 工作区            ← 管理员在此设工作区限额
  ├── 成员与邀请        ← 仅组织管理员「分配 / 回收」成员组织钱包
  ├── 钱包              ← 取代原「额度」；各角色看自己的组织余额（布局对齐个人钱包）
  └── 上游 / BYOK

（移除）额度 /quota     ← 旧「组织池 ↔ 工作区池」划拨页，不再保留菜单与主路径
```

**布局（对齐个人钱包 `/wallet`）：**

- 同类结构：余额 / 已用等统计区 + 流水（账单）入口。  
- **去掉**个人钱包上的充值 / 兑换 / 在线支付等「自己加钱」区块。  
- 文案说明：额度由组织管理员分配，本页只读余额与流水。  
- 一人多组织或多工作区：用页内组织 / 工作区筛选，或分卡展示「当前用户」在各工作区的组织钱包行——仍只含**自己**的数据。

| 角色 | 在「钱包」页看到什么 | 能否在本页改余额 |
| --- | --- | --- |
| **超管**（若已加入某组织） | **自己的**组织钱包（与成员同构） | 否 |
| **组织管理员** | **自己的**组织钱包（与成员同构） | 否（分配在「成员与邀请」） |
| **普通成员** | **自己的**组织钱包 | 否 |

**与个人钱包的区别：**

| | 个人钱包 | 组织「钱包」 |
| --- | --- | --- |
| 数据 | 当前用户个人余额 | 当前用户各组织钱包 `(user, customer, workspace)` |
| 布局 | 现有 `/wallet` | **同构**（统计 + 流水） |
| 加钱 | 充值 / 兑换等 | **无**；仅组织管理员分配 |

### 7.1 规则

- 绑定 `(user_id, customer_id, workspace_id)`。  
- **查看**：超管 / 组织管理员 / 成员 → 都只看**自己**的组织钱包。  
- **分配 / 回收**：仅**组织管理员**在「成员与邀请」（等管理入口）操作；组织「钱包」页不做全员列表、不开放自充。  
- 余额为 0：**可建**工作区范围密钥；**调用时**拒绝对应扣费。  

### 7.2 离开工作区

1. 该用户在该工作区组织钱包 `balance` **全额退回**工作区可分配额度。  
2. 钱包清零或归档 + 流水「退回工作区」。  
3. 该范围下组织钱包密钥调用失败（或禁用）。  

离开组织：对该组织下所有工作区钱包执行同上。

### 7.3 不做历史令牌迁移

不跑批量改 `billing_wallet` 的脚本。扣费规则以 **令牌范围类型** 为准（§8）：  
选了工作区 → 扣组织钱包；个人范围 → 扣个人钱包。

## 8. API 密钥：范围与扣费（关键修正）

### 8.1 范围选项（已确认）

令牌范围只有两类语义：

| 范围类型 | UI | 扣费账户 |
| --- | --- | --- |
| **个人** | 现有个人范围文案（不出现在「工作区」下拉里） | **个人钱包** |
| **工作区** | 固定格式 `组织名称-工作区名称` | **组织钱包**（该用户在该工作区） |

**工作区选择器没有「个人」选项。**  
「个人」与「工作区」是范围维度上的互斥选择，不是「选了工作区再选扣个人还是组织」。

### 8.2 与「成员能用个人钱包建密钥」的关系

- **能**：创建密钥时选范围 = **个人** → 扣个人钱包。  
- **不能**：范围 = 某工作区，却再选个人钱包——产品上不提供该组合。  
- 因此：凡展示为 `组织名-工作区名` 的密钥，**一律扣组织钱包**。

### 8.3 旧令牌怎么理解（非迁移）

- 不做批量迁移。  
- 上线后逻辑按范围解释：  
  - 带工作区范围的密钥 → 按 **组织钱包** 扣（管理员需保证已给成员分配；余额不足则调用失败）。  
  - 个人范围密钥 → 继续扣个人钱包。  
- 若极旧数据**范围为空 / 无法判定**：按 **个人** 处理 → 扣个人钱包（已确认，不做「报错重建」）。

### 8.4 创建时校验

- 工作区范围：校验当前用户是该工作区成员；**不要求**余额 &gt; 0。  
- 调用时：组织钱包余额不足 → 拒绝本次请求。

## 9. 多工作区 + 一人多组织

### 9.1 加入工作区

- **不**自动加入 `default`。  
- 仅通过 **在某工作区上下文中邀请**（或管理员把成员加入指定工作区）。  
- 邀请 UI：必须选择目标工作区；无「个人」项。  

### 9.2 一人多组织

```text
User
  ├── 个人钱包
  ├── 组织 A（多工作区成员 + 各工作区组织钱包）
  └── 组织 B（可 owner）…
```

- 邀请：已是**该**组织成员 → 拒绝；已是其它组织成员 → **允许**。  
- `users.customer_id` 单字段不够 → 以实现阶段成员表为准。  

### 9.3 再开组织

已登录用户可走「创建组织」再次开户，新建组织并成为 owner。

## 10. 目标信息架构

```text
注册
  ├─ 选型：个人 | 组织
  ├─ 个人 → 个人钱包
  └─ 组织 → 新建组织（可重复创建更多组织）

登录：主按钮 → 下方 OAuth

顶栏：无组织名、无全局工作区下拉

组织页：无「当前上下文」横幅；范围靠页内组织/工作区筛选

组织
  ├─ 组织筛选
  ├─ 工作区（设限额；邀请在工作区维度）
  ├─ 成员与邀请（管理员分配组织钱包）
  ├─ 钱包（各角色：自己的组织余额，布局对齐个人钱包）
  └─ 上游 / BYOK

API 密钥
  ├─ 范围 = 个人 → 扣个人钱包
  └─ 范围 = 组织名-工作区名 → 扣组织钱包
```

## 一、一句话结论

在现网 New API（`https://token.abcyjw.me`）上建设 **「组织 → 工作区」** 多组织组织与额度体系，对齐 [DogRouter 企业方案](https://dogrouter.ai/zh-CN/business) 的控制平面能力；**一期（M1）即含独立上游 / BYOK**（默认全球共享、按组织开通），并完成隔离、配额、邀请协作。

---

## 二、背景与必要性

### 现状

- 已具备：多模型网关、渠道、令牌、个人额度、日志、定价  
- 当前为 **单层用户模型**：适合个人或小团队  
- **缺少**：多组织隔离、组织统一预算、工作区级配额、组织管理员自主邀人、按组织专属上游  

### 业务痛点

| 痛点 | 影响 |
| --- | --- |
| 多家组织共用一套用户体系 | 数据与额度难隔离，不便对外签约 |
| 只能给个人加余额 | 无法按「组织总预算 → 工作区执行」管成本 |
| 无组织管理员角色 | 事事依赖平台超管，难规模化 |
| 大组织要自带 Key / 专属线路 | 仅全球共享无法满足合同要求 |

### 建设目标

> 在 **配额 / 组织 / 工作区** 范围内，按策略管理已审批的模型流量；并支持按组织开通独立上游或 BYOK。

---

## 三、方案概览

### 组织架构

```text
平台（我们）
  └── 组织（签约租户）
        └── 工作区（业务线 / 环境，如 default、生产、测试）
              └── 成员 + API 令牌 + 工作区预算
```

### 各方怎么用

| 角色 | 能做什么 |
| --- | --- |
| **平台超管** | 开组织、充值、全局渠道与定价；为组织开通上游模式 / 渠道绑定 / BYOK |
| **组织管理员** | 建工作区、邀请员工、划拨预算、管理 BYOK 凭证（若已开通） |
| **组织成员** | 在工作区下申请令牌、调用模型（扣工作区预算） |
| **未入组织的个人用户** | 保持现状：个人余额；**永不走组织 BYOK** |

### 钱和额度怎么走

```text
我们给组织充值（组织池）
    → 组织管理员划拨到各工作区
        → 员工用工作区令牌调用
            → 只扣「工作区池」
```

要点：

- 组织调用 **不消耗** 个人钱包  
- 工作区预算不足即停  
- **默认** 所有组织走平台共享上游（如 BasicRouter）  
- **可选**：为组织开通独立上游绑定，或组织自带 Key（BYOK）；仍扣工作区池（可配服务费倍率）  

### 组织怎么进来

1. 用户先注册个人账号  
2. 组织管理员发邀请（链接/邮箱）  
3. 接受后加入该组织（**同一时刻只能属于一家组织**）

## 五、分期与交付物

| 阶段 | 内容 | 业务价值 |
| --- | --- | --- |
| **M1（一期）** | 组织/工作区/成员/邀请；充值划拨；工作区扣费；隔离；**独立上游/BYOK** | 可签约控额，并可接专属上游 |
| **M2** | 使用账本、导出、分群、预算预警 | 组织看见消耗、运营分群 |
| **M3** | 模型白名单、限流（审批流 M3.1） | 只跑已审批模型 |
| **M4** | 在线充值、流水/授信/开票（轻）、成本对账 | 收款结算产品化 |
| **M5** | SSO、审计增强、策略包、SLA 指标 | 大组织治理（加购） |
| **按需** | 税务自动化、上游勾兑、审查、护栏、风控台 | 见设计 Part B §B.9 |
| **暂不做** | 机构层 | 控制复杂度 |

**建议**：批准 **M1（含 BYOK）** 排期；粗估约 **29 人天**（见任务文档）。**未动代码。**

## 六、一期验收标准（可感知）

1. 能创建组织 A、B，双方数据互不可见  
2. 组织管理员能邀请成员并分配到工作区  
3. 能给组织充值并划到工作区；调用只扣工作区预算  
4. 工作区没钱时调用失败，且不影响个人余额  
5. 默认走平台共享上游；可为组织开通 **独立上游 / BYOK**；个人令牌只走共享渠道  
6. BYOK 相关 API/日志 **不出现完整上游 Key**

## 七、资源、风险与依赖

### 依赖

- 现网 New API 稳定（渠道、定价、令牌已验证）  
- 命名与规则已对齐（组织 / 工作区）  
- BYOK 加密密钥来源约定（环境变量等）  

### 主要风险

| 风险 | 说明 | 应对 |
| --- | --- | --- |
| 范围膨胀 | 机构、复杂审批一并上 | 已砍机构；策略/SSO 后置；BYOK 默认 shared |
| BYOK 密钥安全 | 托管泄露面 | 加密存储、脱敏、审计无明文；个人令牌隔离 |
| 收款合规 | 多组织在线收款 | M1 超管线下充值；在线支付放 M4 |
| 研发周期 | 组织权限、额度、选渠触及主路径 | 严格按 M1；shared 路径保持现网行为 |
